## One alternating right punch is missed after a tracking jump

The alternating video shows six extension/return movements. At about **REC 56.37 seconds**, the right-wrist image estimate jumps from y = −0.56 to +0.87 torso-length units in roughly 100 ms. Image speed is **14.25 torso lengths/second**, just above the detector's hard limit of 14. The right-hand reason becomes `TRACKING JUMP · HOLD GUARD`, and the detector clears its learned guard.

The next right-hand extension is visible around video **57.7–57.9 seconds** (about REC 56.7–57.0). Right-hand observations remain `Unarmed`, so it does not commit. Wrist confidence remains approximately 0.8–0.9; the miss is explained by guard reset/reacquisition, rather than a missing wrist or failed bag contact. The other five alternating movements commit and hit.

The code responsible is `BoxingPunchIntent.Observe`: the speed-jump branch calls `ResetHistory`, which clears `GuardLearned`. The useful correction is to quarantine an isolated inconsistent observation and recover from a short observed return to the existing guard. Raising the jump threshold globally would weaken protection against erroneous strikes and is not justified by this one sample. Any change needs replay coverage for this miss, real disappearance/re-entry, abrupt joint jumps, rapid alternating punches and idle behavior.

| Stage | Median |
|---|---:|

| CPU scheduling call | 0.09 ms |
| Scheduling → GPU readback callback | 48.42 ms |

| Native model computation, within the preceding interval | 41.57 ms |
| Capture availability → punch decision | 101.75 ms |
| Decision → recorded bag hit | Approximately 56.6 ms |
| Capture availability → recorded bag hit | Approximately 168.9 ms |

The native computation is part of readback-to-consumption time, not an additional serial stage. Medians of separate stages are not necessarily additive. Decision p95 is **120.32 ms**. The hit timing uses first recorded hit-counter transitions and is rounded to rendered-frame precision; exposure, screen display and time from actual motion onset to the sampled observation are excluded.

The main pipeline opportunity is the roughly 48 ms spent waiting for GPU readback before native inference begins. Retain MediaPipe Full and evaluate an earlier/smaller readback or a native camera-buffer input path, measuring the result on the phone. Camera placement alone does not remove this delay. No speedup is claimed by this analysis.
