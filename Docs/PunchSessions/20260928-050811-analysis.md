## Likely performance issue

Almost every long pose interval is adjacent to delivery of a new pose observation: 702 of the 706 intervals exceeding 50 ms end one logged avatar frame before a new observation appears. This strong association warrants profiling inference scheduling, GPU/render contention, readback and grounding. It does not isolate a specific function or prove that GPU work alone is responsible. Optional JSON recording also needs an on/off comparison. The current log does not include a Unity CPU/GPU profiler trace.

At approximately 10 independent observations/second, requiring another observation to commit usually costs an extra 100 ms. Increasing rendered avatar FPS alone will not remove that recognition delay. Likewise, requesting 60 camera FPS in the settings does not mean inference produces 60 observations/second.

## Code findings and priorities

1. **Improve negative-movement rejection before increasing sensitivity.** `PunchIntent.Observe` applies `verticalRaise` only while in Guard. Once Candidate is entered, it does not recheck that condition before commitment. It only rejects upward movement at onset, not downward movement after an overhead pose. Its current guard band also allows wrists considerably above shoulder level. The phone data exposes movements absent from the simpler synthetic negatives.
2. **Use this session as a replay regression fixture.** Preserve intended single-hand and alternating strike candidates while rejecting the confirmed raise/lower cases. Do not label every event solely from the prompt window; synchronize the video first.
3. **Reduce inference-related frame stalls and recognition delay.** Measure scheduling, preprocessing, GPU work, readback and final rendering on this phone. Consider earlier commitment only for strong, well-disambiguated evidence after the negative cases are handled. Lowering thresholds globally would increase false hits.
4. **Make readiness truthful.** The current READY status reports fresh input and an idle animation state, not whether the per-arm recognizer has acquired guard. Expose left/right acquisition and rejection reasons so an apparently idle avatar is explainable.
5. **Validate presentation against the screen recording.** Bone motion in JSON does not prove natural motion or display smoothness. Synchronize using the REC timer/frame IDs.
